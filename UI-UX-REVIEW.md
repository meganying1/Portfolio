# Portfolio UI/UX review

Reviewed October 5, 2026. Scope: the homepage and all nine project pages in the current workspace, with visual inspection at 1440 px desktop and 390 px mobile widths, plus targeted 414 px and 320 px checks. Project narratives were reviewed for presentation and scanning, not rewritten.

The portfolio already feels restrained, professional, and cohesive. Its shared typography, narrow reading measure, quiet separators, and real engineering imagery suit the work. The biggest improvements would make the evidence easier to inspect and the browsing path easier to resume. A redesign is unnecessary.

## What already works well

- **Site cohesion:** all ten pages share the same palette, font, title scale, 704 px maximum measure, separators, caption language, and resource styling. The homepage and project pages already feel related.
- **Visual restraint:** generous desktop margins support the reading measure. The site does not need decorative backgrounds, oversized titles, card shadows, a fixed progress bar, or an elaborate homepage navbar.
- **Hierarchy:** the 24 px page title, semibold section headings, stable section gaps, numbered figures, and quieter captions make the case studies readable. Improve media inspection before increasing the type scale or adding metric panels.
- **Navigation:** the 64 px sticky project bar consistently shows the current project and keeps All projects available. Its return anchor landed about 24 px below the viewport top in the verified flow. Adjacent-project links are already present.
- **Accessibility foundations:** body text is 16 px with generous leading; secondary gray text has approximately 5.66:1 contrast against white; native links, details, headings, and figure captions are used; the skip link and visible keyboard outline are present. The projects disclosure toggled with Enter and showed its blue focus outline.
- **Responsive behavior:** all nine case studies fit the 390 px viewport without page-level horizontal overflow. At 320 px, the battery table scrolls within its own region (approximately 311 px content in a 288 px region), and the slide controls remain 44 × 44 px. Table scrolling can be made more discoverable with a subtle edge cue when overflow exists and a labeled, keyboard-focusable wrapper.
- **Motion:** the current 160 ms disclosure transition has a clear purpose, stays interruptible, and settles immediately for keyboard activation or reduced motion. Keep immediate page navigation and static reading. Fades, page slides, parallax, and scroll reveals would add delay without making the engineering work clearer.
- **Loading structure:** image dimensions and crop aspect ratios reserve space, and source-size caps avoid unnecessary image enlargement. No artificial skeleton or entrance sequence is warranted. Cold-network loading performance was not measured.

## Reusable rules and components to standardize

| Pattern                              | Rule                                                                                                                                                                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Page shell and sections**          | Keep the existing width, responsive gutters, title scale, body type, spacing tokens, and subtle separators. Use shared tokens rather than page-specific overrides                                                       |
| **Project row**                      | Entire row is one link; description remains visible; one persistent interaction cue; date uses shared secondary typography; all images center inside the same thumbnail frame                                           |
| **Experience row**                   | Original brand artwork in consistent frames; optical scaling stays shared; logo centers between separators, including the date on mobile                                                                                |
| **Project opening**                  | Shared title and description, Overview, then recognizable lead media related to the homepage thumbnail. Reuse current assets and prose                                                                                  |
| **Figure**                           | Shared standard/compact/wide variants, source-size limits, preserved aspect ratio, sequential numbering, and left-aligned captions matching the image width. Analytical detail receives an explicit enlargement control |
| **Figure pair**                      | Pair only when the comparison helps. Stack before either image becomes too small to interpret; use the 640 px compact breakpoint as the initial common rule                                                             |
| **Media viewer**                     | One inspection pattern for figures and slides, with a named trigger, caption, close button, Escape, focus containment/restoration, and no swipe requirement                                                             |
| **Project navigation and resources** | Persistent return link, preserved browsing context, labeled previous/next destinations, 44 px standalone targets, and accurate Open/Download wording                                                                    |
| **Feedback**                         | Existing brief color feedback, hover capability queries, clear focus outlines, quiet press feedback, and immediate keyboard navigation                                                                                  |

## Prioritized implementation order

1. **Make engineering media inspectable:** fix the pair breakpoint and add one shared larger-view pattern. This benefits the most pages.
2. **Preserve the expanded project list on return.** Keep the selected-work default for first visits.
3. **Clarify homepage links and navigation actions.** Persistent project cue, labeled pager, and correct download wording.
4. **Normalize project openings and improve source imagery.** Move existing media earlier on Well driller and Chinese checkers; replace weak originals and export clean plots where available.
5. **Refine the long battery page.** Reuse the larger-view pattern for slides; add section shortcuts only if the shorter navigation path is useful.

## Verification and limits

The requested alignment changes were verified through browser screenshots and geometry measurements: all nine thumbnail contents centered at desktop and mobile sizes, and all five mobile logos centered within their complete rows. Desktop logo centers differ from the border-inclusive row center by at most approximately half a pixel.

Production build, TypeScript checks performed by that build, export verification, targeted formatting checks, and `git diff --check` passed. Export verification covered all ten pages, their local assets, and all nine legacy redirects. No project content was rewritten and no site was published.

This review used a browser viewport, not physical phone hardware. Sticky hover behavior, safe areas, browser chrome, and the tactile feel of scrolling still need a device check. The review is of the current local workspace; deployed-site network performance and physical touch behavior were not certified.
